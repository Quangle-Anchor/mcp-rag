# mx-connect Planning Rules

Advisory rules for the planner driving `mx-connect` tools. Each rule
is **scoped** — load a rule file only when the planned action touches
its scope, not as blanket preamble.

This catalog is the single place new rules get listed. The parent
[`README.md`](../../README.md) and [`specs_index.md`](../specs_index.md)
both point here instead of enumerating rule files themselves.

## Audiences

Every rule file declares an `audiences:` frontmatter field with one or both
of these values. Consumers should filter by audience before loading.

| Audience    | Consumer                                                                                                         | Fires                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `spec-scan` | The `mendix-implementation` skill's spec defect scan (`.claude/skills/mendix-implementation`).                   | Once per session, while reading user-supplied spec documents (physical ER, screen specs, microflow specs).                |
| `tool-call` | The `mendix-senior-implementer` agent's RULE LOADING PROTOCOL (`~/.claude/agents/mendix-senior-implementer.md`). | Lazily, the first time the agent is about to make a tool call whose shape matches the rule's `triggers.tool-call` phrase. |

Most rules carry both audiences. A few are tool-call-only because user specs
have nothing to scan for (the rule is about Mendix SDK / expression syntax,
not about the spec's content).

## Adding a new rule

1. Write the rule file in this directory. Open with YAML frontmatter declaring `audiences:`, `triggers:` (one phrase per audience), `status:` (`advisory` or `hard-enforced`), and `enforcer:` (path to the validator) if hard-enforced.
2. Add a row to the table above with the rule's audiences.
3. Do not re-enumerate the rule in `../specs_index.md` or `../../README.md` — both point here.
